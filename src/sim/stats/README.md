# Paired benchmark statistics

`pairedBinary(reference, candidate)` reports candidate minus reference success risk difference, the risk ratio (null when reference risk is zero), the 2x2 paired table, and the exact two-sided McNemar binomial p-value. Its inference therefore uses only discordant seeds. `bootstrapPairedRiskDifference` adds a deterministic paired percentile-bootstrap 95% CI for that risk difference (10,000 resamples by default); it resamples whole pairs rather than treating success rates as independent. This is a practical interval for the expected roughly 200–400 paired seeds, not an exact coverage guarantee.

`bootstrapPairedMeanDifference` bootstraps the mean candidate-minus-reference difference by resampling whole pairs. It is a deterministic percentile 95% CI by default (10,000 resamples and a fixed seed); pass a recorded seed for a different, reproducible stream. It quantifies a mean difference, not a median or stochastic simulation uncertainty beyond the sampled seed population.

`wilsonInterval` is used for binary rates. Declaration reporting deliberately has three denominators: unconditional false-declaration probability is false declarations/all runs; coverage is declarations/all runs; precision is correct declarations/declarations. Precision is null when there are no declarations.

`fixedBudgetDecisionTime` gives a correct declaration its observed time and charges a wrong declaration, abstention, nondeclaration, or declaration after the deadline the full mission budget. It reports the resulting mean penalized time and the number of correct declarations. It is deliberately not called RMST: competing terminal decisions are not noninformative censoring, and a confirmatory analysis should use cumulative-incidence or multistate methods as prespecified.

All analyses reject unequal pairing, duplicate matching (when an adapter is used), non-finite outcomes, and impossible declaration flags. `analyzePairedBatchResults` matches seed, checkpoint, every simulation physics/sensor/environment field, and all prescribed placement fields (source override, robot-start override, and initial heading); it deliberately excludes only the compared algorithm ID. Missing records should be excluded only as whole pairs and their count reported; never pair records merely by array position after independent filtering. `holmAdjust` excludes null (unperformed) tests from its family and preserves their positions.
